# sft-v1: критерії успіху, зафіксовані до навчання

Цей файл комітиться до будь-якого запуску навчання `sft-v1` і після цього не змінюється. Результат подається за цими критеріями без переформулювань, навіть якщо він негативний. Контекст і причини: `docs/interim-report.md`, план: `tasks/plan-full-run.md`.

## Критерії

| Критерій | Умова виконання |
|---|---|
| **Основний** (COBOLEval, sampled n 20) | Δ pass@1 > 0 з нижньою межею інтервалу > 0 **і** вищий compile rate |
| **Додатковий** | COBOLEval pass@10: Δ > 0 з нижньою межею > 0; greedy pass@1 не нижчий за baseline v2 |
| **Guard Python** | HumanEval-Python sampled pass@1 падає не більше ніж на 0.02 (точкова оцінка) |
| **Guard CobolCodeBench completion** | pass@1 не нижчий за baseline v2 за інтервалом **і** частка обрізаних відповідей не вища за baseline v2 більш ніж на 10 пунктів |
| **«Навчання працює»** (утримані 20% задач CodeNet, stdin) | pass@1 адаптера > pass@1 бази, нижня межа інтервалу > 0 |

## Вердикт

| Вердикт | Умова | Наслідок |
|---|---|---|
| Успіх | основний + guard Python + «навчання працює» | результат подається як основний |
| Частковий | «навчання працює» виконано, основний ні | слайс B (дані у форматі COBOLEval) |
| Невдача | «навчання працює» не виконано | дані й гіперпараметри, не формат |

Другий seed лише оцінює розкид: заголовкова таблиця будується за seed 42. Якщо вердикти за двома seed різні, результат позначається як нестабільний.

## Чого ці критерії не охоплюють

- Нові пороги під режим доповнення не додаються: він має допомогти COBOLEval і guard на обрізання, але вимірюється тими самими критеріями.
- Діагностичні правки відповідей моделі (на кшталт `STOP RUN` → `GOBACK`) не потрапляють у заголовкові таблиці. Усе, що не зазначено вище, у звіті позначається як дослідницьке.
- Thinking-режим, CobolCodeBench instruct і слайс B у критеріях не беруть участі.
